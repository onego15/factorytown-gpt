## 実装

- 25×25マスの立体地形、段丘、森林、岩場、川、木橋、水車。
- 8種類の品物と3つの生産系列、全11種類の建設メニュー。
- 固定50ms刻みの生産シミュレーション。加工開始時に材料を消費し、完了時に製品を搬出在庫へ追加。
- コンベアは品物を1個だけ保持し、進行度と在庫を保存。搬送先の受入判定が成功した場合にだけ品物を移す。
- 研究、3レベルの工房強化、4段階の街の成長、集荷所での消費と資金獲得。
- カメラ移動・回転・ズーム、建設プレビュー、無効理由、連続コンベア建設、選択、回転、撤去、レポート、ヘルプ。
- 任意の環境和音・操作音、20秒ごとの自動保存、手動保存、再読み込み復元。

## グラフィック・操作の改善サイクル

1. 基本機能後、1440×1000の実ブラウザ画面を撮影。見出しが余分に改行されていたため、文字サイズと字間を調整。
2. 初期描画では1,861 draw callsを観測。静的な地形、森林、建物、街の広場を材質ごとに結合。インデックス付き／なしの形状が混在して結合に失敗する問題を発見し、非インデックス形状に統一して修正。
3. 初期シーンの最終ビルドで511 draw callsを観測。成長済みの鉄ライン付きの街では623 calls、100フレームの平均間隔16.204ms。これは今回のヘッドレスChrome環境での参考値であり、全端末の保証ではない。
4. 建設時の地面グリッド、色付きゴースト、品種ごとの搬送モデル、工房からの煙、風車、水車、住民、供給で変化する街を整備。
5. 小径を追加して、集荷所と街の広場を視覚的に接続。
6. 1280×720のスクリーンショットで左パネルと建築メニューの重なりを発見。見出しの省略、カード寸法の縮小、詳細パネルの高さ制限・スクロールを追加。要素の矩形が重ならないことと、スクロール後にアップグレードを実行できることをブラウザで再検証。
7. 保存後の倍速の内部状態とボタン表示が一致しない問題を修正し、ブラウザ検証に追加。
8. GIFの初版は連続スクリーンショットから作成。さらに滑らかな動画を録画し直し、WebMから8fps相当で抽出した160枚で最終GIFを作成。

最終GIFの再現例（ffmpegがPATHにある場合）：

```sh
node scripts/record-video.mjs
# docs/video-frames を作成してから実行
ffmpeg -ss 3 -i docs/demo.webm -r 8 -t 20 docs/video-frames/%03d.png
python scripts/video-to-gif.py
```

録画元は `browser-test.mjs` の実際のUI操作で作った `test-save.json`。動画・GIFへ架空のゲーム画面を合成していない。大きな中間PNG群は生成スクリプトを残して削除し、元動画と完成GIFを保存。
